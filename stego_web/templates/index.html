From a private message to verifiable media, with protection at every step.

LAYER / 01 — CARRIER

Hidden in plain sight.

Embed a message or file in image, audio, or video using a chosen start unit and bit depth.

LAYER / 02 — ACCESS

Only the right receiver.

AES encrypts the payload. The receiver’s private key opens the bootstrap holding its location and session key.

LAYER / 03 — PROOF

Signed. Then checked.

RSA-PSS authenticates the encrypted record and layout; SHA-256 checks the preserved media bytes.

LAYER / 04 — VERDICT

A result you can inspect.

Review the verdict and checks. The payload is released only when verification is Authentic.

01 / INPUT VALIDATION

Choose the cover and hidden payload

Use a supported image, audio, or video file. The output is a lossless PNG, WAV, or MKV. Add either a UTF-8 message or one payload file.

Generated automatically from the payload.

02 / SENDER AUTHENTICATION

Load the sender signing key

The sender private key creates the RSA-PSS signature. Its public half is exported with the stego file.

03 / RECEIVER GATE

Select the intended receiver

The receiver public key encrypts the bootstrap. Only its matching private key can recover the packet location and AES session material.

04 / EMBEDDING GEOMETRY

Choose the protected layout

Units 0-2047 hold the RSA-2048 bootstrap. Choose a packet start at or after unit 2048; the receiver recovers both values automatically.

Lowest visual impactBest first choice when the cover has enough capacity.
05 / ENCRYPT, SIGN AND EMBED

Protect the complete record

AES-256-GCM encrypts the payload and metadata, RSA-PSS authenticates the encrypted record and layout, and RSA-OAEP protects the receiver bootstrap. Before encryption and signing, the server hashes preserved media bytes (RGB units, RGBA alpha, and declared PCM sample bytes) with the chosen geometry.
