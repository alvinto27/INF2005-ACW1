01 / SECURITY CONTRACT

WHY

Security Properties and Trust Model

01

Confidential payload

The complete record—not only the user bytes—is encrypted with AES-256-GCM.

02

Intended receiver

RSA-OAEP hides the packet location, depth, length and AES session material.

03

Trusted sender

RSA-PSS authenticates the ciphertext, carrier interpretation and embedding geometry.

04

Media integrity

A reproducible masked SHA-256 hash detects changes without needing the original cover.

Payload bytes are released only when every reachable check produces Authentic.

Frame the four independent security goals. A useful Q&A distinction: the sender public key must still be trusted out of band; the protocol does not provide a PKI.

03 / CARRIER ABSTRACTION

MEDIA-NEUTRAL CORE

One Protocol, Three Carrier Adapters

01PNGIMAGE

Carrier unit: low byte of R, G or B.
Order: row-major, R → G → B.
Fixed data: alpha and 16-bit high bytes.

02WAVAUDIO

Carrier unit: low byte of each PCM sample.
Order: declared interleaved samples.
Fixed data: every other sample byte.

03MKVOPTIONAL VIDEO
+

Carrier unit: RGB low bytes, then s16 audio low bytes.
Fixed data: timing, high bytes and alpha.
Output: lossless FFV1 + PCM.

The protocol core sees carrier units and fixed bytes, not pixels or sample frames. This separation is why the same cryptographic protocol works across media.

The signature is checked before decryption. AES-GCM protects the record and binds the bootstrap geometry. RSA-OAEP determines who can discover and open the packet.

17 / AUTHENTICITY BOUNDARY

HONEST LIMITS

What an Authentic Verdict Proves

INSIDE THE BOUNDARY

  • Encrypted payload + typed metadata
  • Sender-signed ciphertext and geometry
  • Preserved RGB and PCM sample data
  • PNG alpha and multi-byte fixed data
  • Canonical video pixels, audio and timing
AUTHENTIC≠UNCHANGED FILE BYTES

OUTSIDE THE BOUNDARY

  • Overwritten cover LSBs
  • PNG ancillary and WAV non-sample chunks
  • Many container tags and display metadata
  • Real-world sender identity / PKI
  • Replay protection and key management
Authentic means the received carrier matches the protocol’s signed canonical interpretation. It is not a claim that every file byte is unchanged or that the public key belongs to a named person.
